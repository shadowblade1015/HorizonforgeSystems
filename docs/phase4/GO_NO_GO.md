## Remediation order and estimates

1. **Protect progress first:** P4-01 single-writer/conflict detection/raw retention, 2-4 engineering + 1-2 QA days. Cover lifecycle, import/reset/recovery, future versions and update approval. Existing test green is not a waiver.
2. **Collect correct deployment evidence and physical/AT gates:** typically 1-3 QA/release days once read access/devices/accounts exist; external availability is not included. Do not disable deployment protection or deploy merely to obtain evidence.
3. **Small PWA/accessibility fixes:** P4-03/P4-04 and P4-05, about 1.25-2.5 engineering + 1-1.5 QA days together. Independent regressions and dependent upgrade checks required.
4. **Solver performance:** P4-02, 1-3 engineering + 1 QA days. Move work off-thread/cancel safely; preserve semantics. F15 wording/memoization, additional 0.5-1 day plus fixture QA after a false-positive fixture exists.
5. **Commercial/native channels separately:** web ads 3-7 implementation + 2-4 QA days as a preliminary integration allowance; publisher/CMP approval duration unknown. Android baseline 10-25 engineering + 3-8 QA days, assuming Capacitor-like packaging; native P1 fixes and integration may overlap, not simple additive estimates. No selected SDK/package exists, so confidence is low.

For an ad-free web/PWA re-certification, allow roughly **5-12 engineering days and 3-6 QA/release days**, with some parallel work, excluding external access/approval delays and broad redesign. These are planning ranges, not commitments. No framework/backend rewrite is needed to repair the demonstrated web defects.
